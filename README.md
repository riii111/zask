# zask

![dashboard](https://github.com/user-attachments/assets/47a720b8-bf98-4b92-ac51-4fee14fc79e7)

A tmux-native process manager for local development, written in Zig.

zask opens a tmux workspace for your API, workers, frontend, and Docker Compose.
Start, stop, restart, and jump to services from one project config.

## Concept

> Keep the local development environment visible, repeatable, and boring.

zask started from project-local tmux scripts that were useful enough to keep,
but too implicit to share or maintain. It keeps that workflow: local config,
predictable tmux windows, and commands that operate on the processes you
actually use while coding.

## Features

![switch pane](https://github.com/user-attachments/assets/64214681-3a0d-4d15-ac01-c3d26671d70a)

- Keep services in a persistent tmux session, with a dashboard and live monitor.
- Start and stop one service, a group, Docker, or the whole workspace.
- Start services in order and wait for dependencies to be ready.
- Jump to a service window or read saved output after the workspace closes.
- Restart on file changes or failures, with restart reasons in the monitor and logs.

## Installation

Install the latest release:

```bash
curl -fsSL https://raw.githubusercontent.com/riii111/zask/main/install.sh | sh
```

Or build from source:

```bash
git clone https://github.com/riii111/zask
cd zask
zig build install
```

With Nix:

```bash
direnv allow
zig build install
```

### Shell completion

Run `zask completion` for setup instructions for zsh, bash, or fish.
Completion includes service names, groups, and start profiles from your config.

## Quick Start

Run from your project directory:

```bash
zask init
```

`zask init` prints the path to the generated config. Edit it to match your
services. To import an existing Procfile, use `zask init --from Procfile.dev`.

```bash
zask check
zask open
```

`zask check` checks the config, commands, and ports before you open a session.
Add `--prechecks` to run your configured precheck commands too.

During development:

```bash
zask status
zask restart api
zask logs api
zask stop backend
zask close
```

`zask logs api --saved --tail 100` reads saved output, even after `zask close`.
Use `zask logs api --path` to find the log file for your editor.
Docker Compose output is not saved.

For scripts, `zask status --json` reports service state as JSON.
`zask wait api && npm run e2e` waits for the API to be ready before running tests.
Run `zask help` for the full command list.

## Configuration

Keep a `zask.json` or `zask.jsonc` in the project root; dot-prefixed names also
work. JSONC accepts comments. Use `--config <file>` to choose a file explicitly.

Configs created by `zask init` live under
`${XDG_CONFIG_HOME:-~/.config}/zask/<project>/`. You can also load one by name:
`zask demo open` uses the config whose `project.name` is `demo`.

A project with an API, a worker, and a frontend:

```json
{
  "project": {"name": "demo", "root": "."},
  "docker": {"compose": "compose.yaml"},
  "groups": [
    {
      "name": "backend",
      "services": {
        "api": {"dir": "backend", "command": "cargo run --bin api", "port": 18080},
        "worker": {"dir": "backend", "command": "cargo run --bin worker"}
      }
    },
    {
      "name": "frontend",
      "services": {
        "web": {"dir": "frontend", "command": "npm run dev", "port": 5173}
      }
    }
  ],
  "startup_order": [
    {"docker": true},
    {"group": "backend", "wait_ports": [18080]},
    {"group": "frontend"}
  ]
}
```

A service can be just a command string, such as `"worker": "cargo run"`.
`zask add scheduler "cargo run --bin scheduler" --group backend` adds one
without rewriting the rest of the config, including JSONC comments.

Set `env_file` on the project, a group, or a service to load a `KEY=value` file.
Project and group paths are relative to the project root; service paths are
relative to that service's directory.

Add `"watch": {"paths": ["src"]}` to a service to restart it on file changes.
Use `include` and `exclude` to filter watched files.
Add `"restart_on_failure": {"max_retries": 3, "delay_ms": 1000}` to retry failed
runs. Services stopped with `zask stop` or Ctrl-C stay stopped.

Service commands run in a non-interactive shell. Use commands such as
`npm run dev`, `make dev`, or `mise exec -- npm run dev` rather than aliases or
functions defined in `.zshrc`.

The [config schema](schema/zask.schema.json) lists all settings.
Configs generated by `zask init` include a `$schema` reference for editor
completion and validation.

## Requirements

- tmux (3.3 or newer for log popups)
- `less` for log popups
- Zig 0.16.0 to build from source
- Docker with Docker Compose, when the config has a `docker` section

```bash
direnv allow

```
